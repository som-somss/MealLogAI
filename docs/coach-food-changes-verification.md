# AI 코치의 음식 추가·빼기 · 2026-11-07

## 동작

“오늘 점심 오이를 100g 추가해줘”, “오늘 점심 마요네즈를 빼줘” 요청으로 실제 식사 기록과 같은 구성의 저장 조합을 함께 수정합니다. “오늘 점심 기록이랑 저장한 시오콘부볶음밥 조합 둘 다 오이를 100g 추가해줘”처럼 조합 이름을 지정할 수 있고, “식사만”, “조합만”도 지원합니다.

- 추가는 앱에 포함된 음식 자료에서 이름·제품·양·영양값을 확인합니다. 정확한 이름을 우선하고, 여러 음식이 일치하면 번호 선택을 받습니다. 없는 음식의 영양값을 만들거나 생성 모델 답변을 저장하지 않습니다.
- 개수 환산은 확인된 자료가 있을 때만 합니다. 계란후라이 한 알 추가는 앱 자료 기준 50g, 98kcal입니다.
- 추가하는 양은 최종 총량이 아니라 더 넣을 양입니다. 기존 음식과 별개 항목으로 추가하고, 답변에 이를 표시합니다.
- 빼기는 지정한 음식 항목 전체를 제외합니다. 같은 음식이 여러 항목이면 번호로 선택합니다. 일부 양만 빼려는 요청에는 남길 최종 양으로 양 수정을 요청하도록 안내합니다.
- 같은 전체 구성의 조합을 자동으로 함께 찾는 기존 규칙을 유지합니다. 조합을 명시적으로 요구했는데 찾지 못하면 어느 쪽도 수정하지 않습니다. 조합을 별도로 지정하지 않았고 같은 구성이 없으면 식사만 수정했다는 결과를 표시합니다.
- 한 요청에는 음식 하나와 작업 하나를 지정합니다. 추가 양 미입력·질문·부정문·여러 작업은 저장하지 않고 안내합니다.
- 저장 조합의 음식 8개 제한, 식사 100개 제한과 마지막 음식 제거 방지를 적용합니다. 빈 식사나 빈 조합은 생성하지 않습니다.
- 기존 음식, 영양값 미상, 메모와 나머지 필드는 보존합니다. 추가·제외한 음식의 영양값에 따라 합계가 바뀝니다.

## 저장과 검증

`db/coach-food-changes.sql`의 `meallog_coach_change_foods`가 식사·조합·결과 대화를 한 트랜잭션에서 처리합니다. 본인 소유권, 기존 RLS, generation 보호, 음식 스냅샷과 조합 revision 검증, 요청 ID 재시도 처리를 유지합니다. 전체 음식 배열을 덮어쓰는 입력을 받지 않고 잠근 원본에서 항목 하나만 추가하거나 제거합니다. SQL 함수는 SECURITY INVOKER, 빈 search_path, 인증 사용자 실행만 허용합니다.

- Node 테스트 44개 통과: 기존 36개와 추가·삭제 8개. JavaScript 68개 문법 검사와 diff 검사 통과.
- 실제 DB authenticated 권한 테스트: 두 대상 추가·삭제와 원본 복원, 영양값·나머지 음식·메모 보존, revision 및 메시지, 중복 요청 재시도, 오래된 revision, 없는 대상·대화, 마지막 음식, 잘못된 양·인덱스, generation 보호를 검증했습니다.
- 두 번째 대상인 조합의 8개 제한 오류를 발생시켜 앞서 실행한 식사 UPDATE와 성공 메시지까지 전부 롤백되는 것을 확인했습니다. DB 테스트 데이터는 모두 롤백했습니다.
- 로그인 브라우저에서는 별도로 만든 테스트 조합에 오이 100g을 추가하고 다시 뺐습니다. UI 완료 문구와 실제 DB의 15kcal, 항목 수 2→3→2, revision 0→1→2를 확인했습니다. 식사와 조합 동시 변경은 위 DB 테스트에서 검증했습니다.
- 브라우저 테스트 조합과 해당 테스트 대화는 검증 후 제거했습니다. 실제 점심과 저장 조합의 음식 JSON 지문은 전후 동일합니다.
- 함수 권한을 조회했고 새 함수 관련 보안 advisor 지적은 없습니다. 기존의 다른 경고는 이번 작업 범위에서 변경하지 않았습니다.
