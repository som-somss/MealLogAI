# AI 코치의 음식 교체 · 2026-11-07

## 동작

“오늘 점심 계란후라이를 삶은 계란 한 알로 바꿔줘”처럼 기존 음식과 새 음식의 양을 지정하면 실제 식사와 같은 구성의 저장 조합을 함께 교체합니다. “오늘 점심 기록이랑 저장한 시오콘부볶음밥 조합 둘 다 계란후라이를 삶은 계란 한 알로 바꿔줘”처럼 조합 이름을 지정할 수 있고, “식사만”, “조합만”도 지원합니다.

- 기존 음식 항목 전체를 원래 위치에서 교체합니다. 항목 수와 다른 음식의 순서·내용·메모는 그대로 유지합니다. 마지막 음식 하나나 이미 8개인 조합도 교체할 수 있습니다.
- 새 음식과 영양값은 앱 음식 자료에서 찾습니다. 새 음식의 개수 환산은 확인된 자료가 있을 때만 하며, 기존 음식의 영양값을 새 음식에 재사용하지 않습니다.
- “계란후라이를 50g으로 바꿔줘”는 기존 양 수정으로 처리합니다. “계란후라이 대신 오이 100g으로 교체해줘”처럼 ‘대신’도 지원합니다.
- 새 음식의 양 누락, 모호한 음식, 부분 교체, 여러 음식·작업, 질문·부정문은 실행하지 않고 구체적인 요청을 안내합니다.
- 새 음식 자료나 기존 항목이 여러 개면 번호로 선택하며, 선택 단계가 이어져도 원래 바꿀 음식과 새 음식 정보를 보존합니다.
- 기존의 자동 조합 연결은 끼니와 전체 구성 일치 방식입니다. 명시적으로 요청한 조합을 찾지 못하면 어느 쪽도 바꾸지 않습니다. 한쪽만 처리되면 답변에 대상을 명시합니다.

## 저장과 검증

`db/coach-food-changes.sql`의 기존 함수에 `replace` 연산을 추가했습니다. 기존 추가·빼기와 호환됩니다. 교체는 두 개의 삭제/추가 요청이 아니라 한 DB 트랜잭션의 항목 교체이며, 식사·조합·완료 대화를 함께 저장합니다. 스냅샷·revision 충돌, 소유권·RLS·generation 보호, 요청 ID 재시도를 유지합니다. 결과에는 전후 음식과 양을 담습니다. 음식 JSON이 이미 같으면 다시 수정하거나 revision을 올리지 않습니다.

- JavaScript 테스트 50개와 69개 파일 문법 검사, diff 검사 통과.
- 새 테스트 6개: 출발/도착 음식 구분, 새 음식 분량 환산, 기존 양 수정 구분, 모호하거나 부정한 요청 차단, 카탈로그·기록의 연속 선택, 마지막 항목·가득 찬 조합 교체. 기존 API 테스트에도 교체 연산 전달을 추가했습니다.
- 실제 DB authenticated 권한으로 식사와 순서가 다른 조합의 각각 올바른 항목 교체, 새 영양값, 다른 음식·메모 보존, 전후 결과, revision·메시지, 재시도, 동일 값 유지, 충돌, 없는 대상·대화, 잘못된 두 번째 항목, generation, 영양값 검증, 8개 조합 교체를 확인했습니다.
- 같은 저장 함수의 기존 추가·빼기 및 두 번째 저장 실패 시 전체 롤백 테스트도 함께 통과했습니다. DB 테스트 데이터는 모두 롤백했습니다.
- 로그인 브라우저에서 별도 테스트 조합의 계란후라이 50g을 삶은 계란 한 알로 교체했습니다. UI의 전후 표시와 DB의 삶은 계란 50g·77.5kcal, 순서·항목 수 유지, revision 0→1을 확인했습니다. 식사와 조합 동시 변경은 DB 테스트에서 검증했습니다.
- 테스트 조합과 테스트 대화는 정리했습니다. 실제 점심과 저장 조합의 음식 JSON 지문은 검증 전후 동일합니다.
- SECURITY INVOKER, 빈 search_path, 익명 실행 차단을 조회했고 해당 함수에 대한 보안 advisor 지적은 없습니다.
