# AI 코치의 음식 양 수정 · 2026-11-07

## 동작

“오늘 점심 계란후라이를 50g으로 수정해줘”처럼 명시적으로 요청하면 실제 식사 기록과 같은 구성의 저장 조합을 함께 수정합니다. “오늘 점심 기록이랑 저장한 시오콘부볶음밥 조합 둘 다 계란후라이를 한 알로 수정해줘”처럼 조합 이름을 지정할 수도 있습니다. 저장 완료 답변은 DB 처리 결과로만 생성하며 외부 생성 모델을 호출하지 않습니다.

- “오늘 점심 기록만 계란후라이를 50g으로 수정해줘”: 식사 기록만 수정.
- “시오콘부볶음밥 조합만 계란후라이를 50g으로 수정해줘”: 저장 조합만 수정.
- 조합 이름을 생략하면 끼니, 전체 음식 이름·브랜드·단위·양·영양값이 같은 조합을 찾습니다. 영구 연결 관계를 추가한 것은 아닙니다.
- 여러 대상이 있으면 번호로 제시하고 “선택 1”로 선택합니다. 같은 대화와 선택 날짜에서 15분간 유효하고 현재 기록을 다시 검증합니다.
- 조합까지 명시적으로 요청했는데 찾지 못하면 어느 쪽도 수정하지 않습니다. 조합을 따로 지정하지 않았고 같은 구성이 없으면 식사만 수정하고 결과에 알립니다.
- 한 요청에서 음식 하나의 최종 양 하나를 받습니다. 여러 음식, 상대적인 증감, 모호한 요청은 구체적인 양을 다시 묻습니다.
- 개수는 앱 음식 자료에 하나의 정확한 환산량이 있을 때만 변환합니다. 계란후라이 1개는 앱 자료 기준 50g, 흰쌀밥 반 공기는 105g입니다. 환산 자료가 없으면 g/mL 등 기록 단위로 다시 묻습니다.
- 수정한 음식의 기존 영양값을 양에 비례해 계산하고 다른 음식과 메모는 보존합니다. 영양값 미상은 미상으로 유지합니다. 같은 양이면 원래 정밀도와 조합 revision도 그대로 유지합니다.
- 저장 후 식사 화면과 조합 목록을 새로 읽습니다. 브라우저 캐시 버전은 6366입니다.

## 저장 보장

`db/coach-resize.sql`의 `meallog_coach_resize`는 식사, 조합, 결과 메시지를 한 트랜잭션에서 처리합니다. 본인 대화·식사·조합 소유권, 기존 RLS와 기록 초기화 generation 보호를 유지합니다. 함수는 SECURITY INVOKER와 빈 search_path를 사용하며 익명 실행을 차단했습니다.

요청 ID 재시도는 기존 결과를 반환합니다. 음식 JSON 스냅샷과 조합 revision이 달라지면 충돌로 처리하고 일부만 저장하지 않습니다. 영양값은 DB 원본에서 계산합니다. 두 번째 대상 저장에 실패하면 첫 번째 대상 변경도 롤백됩니다.

적용 migration: `coach_resize_meals_and_combinations`, `coach_resize_preserve_unchanged_food`.

## 검증

- JavaScript 테스트 36개 및 67개 파일 문법 검사 통과.
- 새 테스트는 명시적 요청 해석, 한 알 환산, 한쪽만 수정, 전체 구성 일치, 모호한 대상 선택·만료, 인증 사용자 범위, RPC 재시도 및 실패 응답을 검증합니다.
- 실제 DB에서 authenticated 권한으로 식사와 조합의 100g→50g 변경, 영양값 계산, 나머지 음식·메모 보존, revision, 메시지 저장, 요청 재시도, 같은 양 유지, 오래된 revision, 없는 대상·다른 대화 접근, 두 번째 저장 실패 시 전체 롤백, generation 보호, 영양값 미상을 검증했습니다. 모든 테스트 데이터는 트랜잭션 롤백했습니다.
- 새 함수 관련 보안 advisor 지적은 없습니다. 기존의 다른 경고는 이번 작업 범위에서 변경하지 않았습니다.
- 로그인된 실제 브라우저에서 점심과 이름을 지정한 조합에 “계란후라이를 한 알로 수정해줘” 요청을 실행했습니다. 양은 이미 50g이므로 양쪽 모두 50→50g이라는 실제 DB 결과를 확인했습니다. 사용자의 음식 양을 시험용으로 바꾸지 않았습니다. 식사 홈 화면의 402kcal 동기화도 확인했습니다.
