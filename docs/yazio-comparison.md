# YAZIO 비교와 MealLog AI 보완 순서

확인일: 2026-11-08. YAZIO 공식 안내와 MealLog AI의 현재 소스를 비교했습니다. YAZIO 기능은 무료·Pro 및 플랫폼에 따라 차이가 있으며, 아래 비교는 직접 앱 전체를 사용해 평가한 결과가 아닙니다.

| 영역 | YAZIO 공식 안내 | MealLog AI 상태와 다음 작업 |
| --- | --- | --- |
| 영양 목표·진행률 | 열량 목표와 탄수화물·단백질·지방 비율 조절 [1] | 이번에 세 영양소의 g 목표·남은 양·초과량·진행 막대 추가. 기존 단백질 목표를 AI 코치와 공유. 비율 기반 설정·날짜별 목표 이력은 후속 범위. |
| 음식 기록 | 사진 추정, 바코드, 최근·자주 먹는 음식 [2][3] | 사진·바코드·영양표·수동 검색·최근 음식·내 조합이 이미 있음. 인식 정확도 우열은 측정하지 않음. |
| 레시피와 인분 | 여러 인분, 조리 단계, 인분 또는 g으로 기록 [4] | 조합과 재료별 양 편집은 있음. 총 조리량·인분 환산·조리 단계 없음. 다음 우선순위: 저장 조합을 2인분 만들어 0.5인분 먹는 경우를 정확하게 기록. |
| 식단 계획·장보기 | Pro에서 미래 식사 계획, 레시피와 장보기 목록 [2] | 날짜별 기록은 있으나, 예정 식단과 실제 섭취를 구분하는 흐름 및 장보기 집계는 없음. 계획을 섭취량에 미리 더하지 않는 구조부터 필요. |
| 상세 영양 | Pro에서 식이섬유·당·소금 등 상세 분석 [2] | 주로 열량·탄수화물·단백질·지방을 저장. 출처별 단위·누락 여부를 유지하는 식이섬유·당·나트륨 확장이 필요. |
| 건강 앱 연결 | Pro에서 지원되는 활동 서비스와 자동 연결 [2] | 물·체중·운동·수동 걸음·아이폰 단축어는 있음. 네이티브 건강 플랫폼 자동 연동은 없음. |

## 차별화 방향 · 2026-11-08 추가 조사

**제품 약속: 내가 먹는 식사를 기억하고, 말로 고친 내용을 다음 기록에 정확히 이어 주는 식사 비서.**

우선 대상은 집밥·반복 메뉴를 자주 기록하고, 매번 재료와 양을 다시 입력하는 것이 번거로운 사용자입니다. 현재 사용자가 요청한 조합 저장·계란 한 알의 양 보정·여러 재료 동시 수정이 출발점입니다. 이 수요가 전체 시장을 대표한다는 뜻은 아니며, 아래 방향은 검증할 제품 가설입니다.

YAZIO도 AI 사진 분석, 분석 결과 수정, 식사 템플릿을 지원합니다 [3]. 개인 메뉴·즐겨찾기·자주 먹는 음식도 검색에서 우선합니다 [9]. 따라서 사진 AI나 즐겨찾기 자체를 독점적인 장점으로 홍보하지 않습니다. **수정 → 확인된 개인 기준 → 다음 식사 재사용**의 전체 흐름을 짧고 믿을 수 있게 만드는 데 집중합니다.

| 관찰과 근거 수준 | MealLog AI가 해결할 문제 | 구체적인 제품 방향 |
| --- | --- | --- |
| **공식 확인:** 공개 음식 수정은 Pro 대상이고 검증 표시 음식은 수정 불가. 개인 음식은 수정 가능 [5]. | 포장지와 앱 값이 다르거나 내 조리법에 맞지 않을 때 개인 기준을 쉽게 남겨야 함. | 공용 DB 원본·개인 보정값·근거를 구분. 수정한 제품/분량을 다음 검색과 기록에 재사용하고 적용 범위를 보여 줌. |
| **공식 확인:** 개인 레시피는 기기에 저장되며 기기 간 동기화가 안 되는 경우가 있다고 안내 [6]. | 공들여 만든 내 레시피를 다른 기기에서도 믿고 다시 쓰고 싶음. | 계정에 저장된 조합의 최신 버전·저장 상태·변경 이력을 보여 주고, 재접속·동시 변경·오프라인 실패를 검증. MealLog의 기존 서버 저장을 기반으로 보강. |
| **공식 확인, 공통 한계:** 사진 AI의 양·영양값은 대략적인 추정이며 사용자 수정 필요 [3]. | 기름·소스·밥 양이 보이지 않는 사진에 정밀한 숫자를 붙이면 잘못 믿기 쉬움. | 추정과 확인된 값을 구분하고, 이미 승인한 내 분량을 재사용. 모르는 재료·양만 질문. 근거 없는 신뢰도 %나 영양값 범위는 만들지 않음. |
| **일부 후기:** 영국 App Store에서 팝업·연속 기록·게임 요소가 입력을 방해한다는 불만. 같은 페이지에는 편리함과 AI를 칭찬하는 후기도 있음 [7]. | 기록을 끝내기 전에 불필요한 화면을 통과하고 싶지 않음. | 기록·수정·완료를 우선하는 홈. 연속 기록·친구·응원은 선택형으로 설계하고, 다시 기록하기 쉽게 안내. |

공식 문서는 특정 버전의 제약을 설명하며 영구적인 결함을 입증하지 않습니다. 후기 표본은 전체 이용자의 불만 비율이나 성능 우열을 뜻하지 않습니다. 일시적인 오류 공지를 장기 차별화 근거로 사용하지 않습니다. 한국 음식 인식률이 YAZIO보다 높다는 주장도 아직 비교 측정하지 않았습니다.

## 개발 우선순위

영양 목표·진행률은 이미 배포했습니다. 이후 순서는 위 차별화 방향에 맞춰 다음과 같이 조정합니다. 아래 항목은 **후속 개발 범위**이며, 이번 조사에서 구현 완료한 기능이 아닙니다.

1. **내 식사 다시 기록하기 + 개인 분량 + 조합 인분 계산.** 내 조합을 불러와 오늘 달라진 양만 바꿔 기록하는 흐름을 먼저 완성합니다. “지난번 볶음밥, 오늘은 밥 반만”에서 기준 버전과 밥의 양을 확인하고 나머지는 유지합니다. 전체 조리량·인분·먹은 비율을 구분합니다. 사용자가 확인한 한 알·한 공기의 기준은 음식·조리법별로 저장하며 모든 계란이나 모든 밥에 일괄 적용하지 않습니다.
2. **고친 내용의 확인·재사용·되돌리기.** 기존 실제 수정과 식사 이력 기능을 연결합니다. 오늘 기록만 바뀐 것과 기본 조합까지 바뀐 것을 명확하게 표시합니다. 식사와 조합을 함께 되돌리는 기능은 별도 구현·원자성 검증이 필요하며, 현재 식사 되돌리기가 조합까지 복원한다고 안내하지 않습니다. 원본 DB/사진 추정/사용자 확인 값의 출처도 재사용 과정에서 유지합니다.
3. **한국 집밥에 맞는 기록과 다음 식사 선택.** 밥·반찬·양념, 조리 전후 기준, 편의점 제품의 기준량을 구분합니다. 조리 전후 무게를 임의로 환산하지 않습니다 [8]. 확인한 내 메뉴 중에서 상황에 맞는 후보와 이유를 제시하고, 개인 기억에 사용자의 승인·수정·삭제 경로를 유지합니다.
4. **조용하고 빠른 홈.** 지금 기록하기·다시 기록하기·목표 확인을 우선 배치합니다. 응원/연속 기록 등은 선택적으로 보고, 누락 기록을 실패나 실제 미섭취로 단정하지 않습니다.
5. **식단 계획·장보기, 상세 영양, 건강 앱 자동 연동.** 핵심 반복 기록 흐름을 검증한 뒤 확장합니다. 데이터 품질과 연동 플랫폼 비용을 각각 확인합니다. 단식·챌린지 확대는 후순위입니다.

## 첫 개발 묶음의 완료 기준

사용 예시는 목표 동작을 설명하며 현재 자연어 입력 지원 범위를 보장하지 않습니다.

| 사용자 상황 | 완료로 볼 기준 |
| --- | --- |
| “지난번 조합 그대로 오늘 점심에 기록해줘” | 지정한 조합 버전과 음식·양·날짜·끼니를 표시하고 한 번만 저장. 새로고침 후 같은 기록 조회. |
| “오늘은 밥만 반, 계란은 한 알” | ‘반’의 기준이 되는 기존 밥 양을 표시. 계란의 개인 분량이 확인돼 있으면 재사용하고, 없으면 질문. 다른 재료는 유지. |
| “이번 식사만 바꿔줘” / “기본 조합도 바꿔줘” | 요청 범위를 구분하고 저장 결과에 표시. 기존에 사용자가 지정한 범위를 존중. 범위가 불분명한 경우에만 확인. |
| “총 2인분을 만들어서 0.5인분 먹었어” | 전체 조리 재료의 25%를 식사에 반영. 단순히 ‘0.5’를 전체의 절반으로 처리하지 않음. 원본 조합 유지. |
| “완성한 음식은 800g이고 200g 먹었어” | 확인된 조리 후 총량 기준 25% 적용. 총량이 없으면 조리 전 재료 무게로 추정하지 않음. |
| 조합 수정 후 예전 식사 조회 | 과거 식사의 음식·양·영양값은 당시 저장값 유지. 새 조합이 과거 기록을 소급 변경하지 않음. |
| 연결 끊김·다른 기기 수정·재시도 | 저장 실패를 완료로 표시하지 않음. 충돌 시 최신 상태 재확인. 중복 식사 생성 방지. |

측정은 같은 반복 식사 시나리오의 현재 수동 흐름을 기준으로 시작합니다. 기록 완료까지 걸린 시간·탭 수·이미 확인한 값을 다시 묻는 횟수·수정 후 재사용 오류를 비교합니다. **잘못된 저장 완료 표시, 과거 기록 오염, 동의하지 않은 기본 조합 변경은 출시 차단 항목**입니다. 1차 개선 목표는 반복 기록 시간 30% 단축으로 두되 이는 아직 측정하지 않은 목표치입니다. 행동 분석이나 원문 수집을 새로 켜지 않고 우선 테스트 시나리오로 측정합니다.

## 이번 목표 기능의 범위

- `홈 → 영양 목표 → 목표 설정`에서 직접 입력. 빈칸은 목표 미설정이며 권장량을 임의로 채우지 않음.
- 선택 날짜의 식사에서 영양소를 합산. 남은 양, 목표 도달, 초과량을 구분. 초과 막대는 100%에서 멈추되 실제 기록량은 표시.
- 미입력 영양소는 0으로 취급하지 않고 해당 영양소 비교만 보류. 기록이 없는 날은 섭취하지 않은 날로 단정하지 않음.
- 현재 목표가 과거 날짜에도 적용됨. 당시 목표 이력 및 열량 목표와 영양소 비율의 자동 환산은 아직 없음.
- 기존 `ai_coach_settings`에 nullable `carbs_goal`, `fat_goal`만 추가. 기존 `protein_goal`, AI 사용·기억 설정, 식사·조합은 유지.
- 계정 변경 시 화면 초기화, 저장 실패 시 입력 유지, 다른 화면에서 목표가 바뀌면 재확인 요청.
