# AI 코치의 여러 음식 일괄 편집 · 2026-11-07

## 동작

“오늘 점심 기록이랑 저장한 시오콘부볶음밥 조합 둘 다 오이 100g과 바나나 50g을 추가하고, 마요네즈를 빼고, 계란후라이를 삶은 계란 한 알로 바꿔줘”처럼 여러 음식의 추가·제외·교체·양 수정을 한 요청으로 처리합니다. 한 번에 2–10개 변경, 하나의 날짜·식사 기록과 하나의 저장 조합을 지원합니다. 단일 변경은 기존 경로를 유지합니다.

- 목록과 이어지는 작업을 명시적으로 분해하고 모든 항목을 검증한 후 한 번에 저장합니다. 하나라도 불명확하거나 빠진 대상이 있으면 일부만 실행하지 않습니다.
- 조합 이름을 지정하거나 “식사만”, “조합만”으로 범위를 제한할 수 있습니다. 자동 연결은 끼니와 전체 음식 구성 일치 기준이며, 명시적으로 요청한 조합을 못 찾으면 저장하지 않습니다.
- 번호 선택이 필요한 음식·기록이 여러 개여도 전체 요청과 이미 완료한 선택을 보존합니다. 선택 중 원본 식사나 조합이 바뀌면 다시 요청하도록 안내합니다.
- 삭제 이후의 이동한 순서가 아니라 각 대상의 원래 음식 위치를 기준으로 변경합니다. 식사와 조합의 음식 순서가 달라도 각각 올바른 항목을 수정합니다. 같은 항목에 두 변경을 지정하면 확인을 요청합니다.
- 최종 항목 수를 검사하므로 마지막 음식 제외 후 새 음식 추가, 8개 조합에서 하나 제외 후 하나 추가가 가능합니다. 최종 식사 1–100개, 조합 1–8개 제한을 유지합니다.
- 추가·교체는 앱 음식 자료와 확인된 분량 환산을 사용합니다. 양 수정은 기존 영양값을 비례 조정합니다. 나머지 음식·메모·미상 영양값은 보존합니다.

## 저장과 검증

`coach-batch.js`에서 전체 요청을 해석·검증하고, `api/ai-coach.js`가 `meallog_coach_batch_edit`를 한 번 호출합니다. `db/coach-batch.sql`은 양쪽의 최종 음식 배열을 모두 계산한 뒤 대상별 한 번씩 수정하고 완료 대화까지 같은 트랜잭션에 저장합니다. 조합 revision은 전체 요청당 한 번만 증가하며, 변경이 없으면 증가하지 않습니다. 기존 단일 변경 함수와 호환됩니다.

- Node 테스트 58개, JavaScript 71개 파일 문법 검사와 diff 검사 통과.
- 새 테스트 8개: 목록·혼합 명령, 조합 이름과 범위, 원래 위치와 새 영양값, 잘못된 절·다른 날짜/끼니·중복 대상·10개 제한, 최종 항목 수, 번호 선택과 스냅샷/시간 만료, 식사/음식 선택, 단일 RPC·재시도·인증·generation·실패 응답.
- 실제 DB authenticated 권한에서 식사와 순서가 다른 조합에 추가·제외·교체·양 수정을 함께 실행했습니다. 각 위치·영양값·다른 음식·메모, 양쪽 합계 8개 변경 결과, revision 1회 증가와 대화 2개를 확인했습니다.
- 요청 재시도, 동일 값 유지, 스냅샷/revision 충돌, 없는 조합과 타인 대화, generation 보호, 잘못된 마지막 변경, 중복 위치, 최종 개수 제한을 검증했습니다.
- 두 번째 실제 UPDATE의 영양값 범위 오류를 유발해 첫 번째 식사 UPDATE와 성공 대화도 함께 롤백되는 것을 확인했습니다. DB 테스트 데이터는 모두 롤백했습니다.
- 로그인 브라우저에서는 별도 테스트 조합에 “오이 100g과 바나나 50g을 추가하고, 마요네즈를 빼고, 계란후라이를 삶은 계란 한 알로 바꿔줘”를 실행했습니다. UI에 네 변경이 표시됐고 DB에서도 기존 밥 보존, 삶은 계란 50g·77.5kcal, 오이 100g·15kcal, 바나나 50g·44.5kcal 및 revision 0→1을 확인했습니다. 식사와 조합 동시 수정은 위 DB 테스트로 검증했습니다.
- 테스트 조합과 테스트 대화는 정리했습니다. 실제 점심과 시오콘부볶음밥 조합의 음식 JSON 지문은 검증 전후 동일합니다.
- 새 함수의 SECURITY INVOKER, 빈 search_path, 익명 실행 차단, authenticated 실행 허용을 조회했습니다. 해당 함수에 대한 보안 advisor 지적은 없습니다.
