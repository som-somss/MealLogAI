# AI 코치 연결·초안 보존 안정화 · 2026-11-08

## 수정한 동작

기록 동기화가 끝나기 전에 코치를 열면 즉시 오류가 나고 창을 다시 열어야 했습니다. 또한 응답을 기다리는 동안 다음 질문을 입력하면 앞선 응답이 도착할 때 입력란이 비워졌습니다. 대기 중 창을 닫으면 이전 작업이 완료되기 전까지 코치를 다시 열 수 없는 문제도 재현했습니다.

- 초기 진입에서 명시적인 `MEALLOG_SYNC_PENDING` 상태만 최대 15초 기다립니다. 동기화가 끝나면 설정과 대화를 불러오며 입력한 질문을 유지합니다. 지연이나 연결 실패는 같은 창의 “다시 연결” 버튼으로 재시도할 수 있습니다.
- 음식 수정·대화 전송은 자동으로 다시 보내지 않습니다. 수동 재시도 시 기존 요청 ID를 유지해 중복 저장 방지를 이어갑니다. 계정/기록 변경이나 권한 오류는 동기화 대기로 취급하지 않습니다.
- 응답이 도착하면 전송 시점 이후 편집되지 않은 입력만 비웁니다. 입력 내용이 바뀌었다가 원래 문장으로 돌아온 경우에도 새 초안을 보존합니다.
- 작업마다 취소 컨트롤러와 유효성 검사를 둡니다. 닫기·Esc·계정 변경 시 진행 상태를 해제해 바로 다시 열 수 있고, 이전 작업의 응답·타이머·종료 처리가 새 화면을 바꾸지 않게 합니다.
- 계정 변경 시 이전 계정의 초안과 대화를 비우는 기존 동작을 유지합니다. 화면을 닫는 동작이 이미 서버에 도착한 저장을 취소한다고 안내하지 않습니다.

## 검증

- 수정 전 실제 `ai-coach.js`를 실행하는 회귀 테스트에서 동기화 대기, 초안 삭제, 재진입 문제가 재현됐습니다.
- 수정 후 Node 테스트 67개, JavaScript 72개 문법 검사와 `git diff --check` 통과.
- 새 UI 테스트 9개는 시간·네트워크를 제어해 동기화 완료/15초 지연/재연결, 일반 오류, 전송 자동 재시도 금지, 새 초안과 동일 문자열 재입력, 초기 연결 중 닫기/재열기, 오래된 응답과 타이머, 계정 변경을 검증합니다. 가짜 DOM과 서버 응답을 사용하며 실제 서버에 쓰지 않습니다.
- 로그인 브라우저에서 새로고침 후 코치 초기 연결과 대화 목록을 확인했습니다. 식사 변경이 실행되지 않는 0g 요청을 보낸 직후 다음 질문을 작성했고, 응답 후와 창 재열기 후에도 초안이 남으며 전송 버튼이 다시 활성화되는 것을 확인했습니다.
- DB에서 테스트 대화가 사용자 질문 1개와 `needs_details` 응답 1개로 저장됐음을 확인했습니다. 테스트 대화만 정리했고, 검증 전후 해당 계정 전체 식사 음식 JSON 및 저장 조합 음식/revision 지문이 동일합니다.
- 브라우저 오류·경고 로그 없음. 테스트 배포의 최근 30분 error/fatal 런타임 로그 조회 결과 없음.
- 동기화 지연·타임아웃 경계는 자동 테스트에서 재현했으며, 실제 네트워크 장애를 인위적으로 만들지는 않았습니다.
- DB 스키마·권한·AI 공급자·환경변수 변경 없음. 기존 실제 조합 저장 및 여러 음식 편집의 회귀 테스트도 통과했습니다.
