# AI 코치의 실제 조합 저장 · 2026-11-07

## 문제와 동작

이전 코치는 “점심 음식을 ○○으로 기억해줘” 요청을 추천으로 처리하고, 실제 저장 없이 저장했다고 답할 수 있었습니다.

이제 명시적인 요청은 생성 모델보다 먼저 처리합니다. “오늘 점심을 시오콘부볶음밥으로 기억해줘”, “어제 점심을 ○○으로 저장해줘”, “방금 기록한 거 ○○이라고 기억해줘”처럼 대상과 이름을 지정하면 본인 식사 기록에서 음식·양·영양값을 읽어 `meal_combinations`에 저장합니다. 개인 기억 추천 활용이나 외부 AI 설정이 꺼져 있어도 사용자의 명시적인 저장 요청은 실행됩니다.

- 식사 기록은 그대로 두고 승인한 조합을 별도로 저장합니다.
- 저장 결과와 채팅 답변은 하나의 DB 트랜잭션으로 기록합니다.
- 동일 요청 재시도는 기존 결과를 반환합니다. 같은 이름·구성은 중복 생성하지 않습니다.
- 같은 이름에 다른 구성이 있으면 기존 조합을 덮어쓰지 않습니다.
- 이름·대상이 모호하거나 기록이 없으면 저장하지 않고 안내합니다. 추천 메뉴나 임의 재료는 저장하지 않습니다.
- 조합에는 기존 기능과 동일하게 음식 1~8개를 담습니다. 자연어 재료 변경·일반 취향 기억 저장은 이번 기능에 포함하지 않습니다.
- SQL은 `SECURITY INVOKER`, 빈 `search_path`, 본인 소유권 확인 및 기존 RLS를 사용합니다. 익명 실행은 차단했습니다.
- 기존 기록 초기화 보호용 generation 헤더를 브라우저에서 API와 Supabase까지 전달합니다.
- 생성 모델의 답변에서 검증되지 않은 저장 실행 표현을 제외하고, 생성 프롬프트에도 조회 전용임을 명시합니다.

## 검증

- JavaScript 테스트: 기존 21개에 저장/오류/동기화/잘못된 완료 문구 검증 7개 추가.
- JavaScript 문법: 65개 파일 통과.
- 실제 DB에서 인증 사용자 권한으로 신규 저장, 원본 재료 보존, 요청 재시도, 별도 요청 중복 방지, 이름 충돌, 기록 부재, 대화 소유권 검증. 테스트 식사·조합·대화는 전부 트랜잭션 롤백.
- `meallog_coach_remember`는 익명 실행 불가, 인증 사용자 실행 가능, definer 권한 없음. 변경 후 보안 advisor에 새 함수 관련 지적 없음. 기존 프로젝트 경고는 이번 범위에서 변경하지 않음.
- 실제 로그인 브라우저에서 사용자가 요청한 점심을 저장하고 ‘내 조합’ 목록에서 재조회. 다섯 재료의 양·영양값을 DB에서도 확인했고 기존 점심 JSON 지문이 전후 동일함.
