# 영양 목표·진행률 검증 · 2026-11-08

## 변경

홈의 열량 요약 아래에 탄수화물·단백질·지방 목표 카드를 추가했습니다. 목표는 g 단위로 직접 설정하며, 빈칸은 미설정입니다. 선택 날짜의 기록 합계와 목표를 비교해 남은 양·도달·초과를 표시합니다. 확인되지 않은 영양소는 0으로 취급하지 않고 해당 비교를 보류합니다.

기존 `ai_coach_settings.protein_goal`을 그대로 공유하고 `carbs_goal`, `fat_goal` 두 nullable 컬럼을 추가했습니다. 기존 코치의 설정 저장은 홈에 갱신 이벤트를 보내며, 코치의 기록 기반 답변도 세 목표를 읽습니다. 기존 AI 사용/기억 설정과 식사·조합은 목표 저장에 포함하지 않습니다.

편집을 열 때 서버 값을 다시 읽고, 저장 때 읽었던 세 목표를 조건으로 비교합니다. 다른 기기에서 목표가 바뀌면 덮어쓰지 않고 재확인을 안내합니다. 읽기·쓰기는 12초 제한이며, 계정 변경과 오래된 응답을 구분하고 실패 시 입력을 보존합니다.

## 확인한 내용

- 전체 Node 테스트 **77개** 통과, JavaScript **75개** 문법 검사 통과, `git diff --check` 통과. 이후 색상 클래스 충돌만 수정하고 관련 테스트 10개를 다시 통과했습니다.
- 새 테스트 10개: 목표 유효성·미설정, 초과/남은 양/0/부분 누락, AI 목표 비교, 선택 날짜와 진행 막대, 서버 저장 및 AI 설정 보존, 신규 설정·해제, 동시 변경·실패, 계정 전환과 늦은 응답, 기존 코치와 공유, 읽기 중 닫기.
- DB 마이그레이션 `nutrition_macro_goals` 적용. 새 컬럼에 authenticated 접근 권한이 있으며 기존 `coach_settings_owner` RLS의 USING/WITH CHECK가 본인 계정만 허용함을 확인했습니다.
- authenticated 역할로 수행한 트랜잭션 검증: 본인 읽기/저장, 다른 계정 삽입 거부, 잘못된 목표 범위 거부, 낡은 목표 조건으로 UPDATE 시 0행, 기존 코치 upsert 후 새 컬럼 보존, 목표 해제, `meallog_coach_context`와 목표 일치. **검증 값은 ROLLBACK**했습니다.
- Supabase security advisor 전후 4개 항목으로 추가·삭제 없음. 이번 설정 테이블 관련 새 경고 없음. 기존 별도 기능 관련 항목은 이번 변경 범위가 아닙니다.
- 로그인된 고정 검증 주소에서 기존 목표를 불러오고 **그대로 재저장**했습니다. 서버의 updated_at 변경, null 목표와 AI 설정 유지, 새로고침 후 홈/설정에서 재조회 확인. 0g 목표는 저장 전에 안내하고 입력 유지.
- 360px 모바일에서 카드와 설정 창을 확인하고, 기존 공통 `.protein`, `.fat` 배경 스타일이 섞이는 문제를 전용 클래스명으로 수정했습니다. 원래 화면 크기로 복원했습니다.
- 실제 계정에 임의의 영양 목표를 적용하지 않았습니다. 비어 있지 않은 값의 저장과 계산은 모의 UI 테스트 및 DB 롤백 테스트로 검증했고, 실제 브라우저에서는 기존 미설정 상태의 저장·재조회를 검증했습니다.
- 검증 전후 해당 계정 전체 식사 음식 JSON 및 조합 음식/revision 지문 일치. 시오콘부볶음밥과 점심 기록을 포함한 기존 데이터 보존.
- 브라우저 error/warn 없음. 검증/운영 배포 최근 30분 error/fatal 런타임 로그 없음. 이번 화면은 주로 DB를 직접 사용하므로 서버 로그만으로 저장 성공을 판단하지 않았습니다.
